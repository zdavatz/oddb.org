# Frontend: Dark mode, Responsive, Result list

Vorfall-Historie und Regeln aus `CLAUDE.md` (ausgelagert am 02.09.2026). Neue Notizen zu diesem Teilsystem gehoeren hierher, nicht in `CLAUDE.md`.

### Drug Search Result List

- Result list columns are defined in `result_list_components` in `src/custom/lookandfeelbase.rb` (default) and overridden per flavor in `src/custom/lookandfeelwrapper.rb`.
- CSS for result list columns is in `CSS_KEYMAP` / `CSS_HEAD_KEYMAP` in `src/view/drugs/resultlist.rb`.
- Twitter share and mail/notify icons have been removed from all result lists.

### Dark mode (`doc/resources/dark.css`, `doc/resources/javascript/darkmode.js`)

- An **overlay**, not a second stylesheet. `oddb.css` is 1099 lines, 88 colour values, zero CSS variables, and it exists **eight times** — one copy per flavor with different accent colours. gcc and generika share 249 of 253 selectors, gcc and mobile 248, so one file keyed on the shared class names covers every flavor.
- **The overlay is generated, not maintained**: `python3 bin/generate_dark_css.py doc/resources/gcc/oddb.css doc/resources/diff.css` emits the block between the two markers in `dark.css`. Hand-enumerating missed 77 colour-setting rules, and worse, a generic `html[data-theme="dark"] a` (specificity 0,1,2) **loses** to `a.subheading:link` (0,2,1) in oddb.css — the links stayed plain blue at 2.1:1 on a dark ground while `--dark-link` sat unused at 8.6:1. Taking the source's own selector and prefixing `html[data-theme="dark"]` is always more specific than the original *and* later in the head, so it wins twice and nothing can be overlooked. `test_every_source_rule_has_a_dark_counterpart` fails if a source rule has none.
- **`diff.css` is a separate linked file** — the `/diff/` pages stayed light until it was fed to the generator too. Order in the head is `diff.css` (link) → `oddb.css` (inlined) → `dark.css` (inlined), so the overlay wins.
- **Backgrounds that carry meaning keep their colour and get dark text**: category badges, deductible markers, AUC factors. Getting that inverted the first time produced light text on light orange for `a.feedback`.
- **The logo is dark green ink on transparency** (`#006B00`–`#008500`, mean brightness 10 %), which lands at 2.6:1 on the dark ground. `brightness(1.7)` lifts it to 6.5:1 and 10.1:1 and leaves the green green; `invert()` would turn it magenta.
- **Everything hangs on `html[data-theme="dark"]`.** Without that attribute the file does nothing, which matters because it is embedded into every page — a user who never switches must see exactly what they saw before. `test/test_view/darkmode.rb` asserts that every colour-setting rule is scoped that way (the only exceptions are `:root` variables and the toggle button itself).
- **The existing colour choice is dead, and that is why this does not use it.** `:styles` / `oddb-blue.css` and siblings differ in 124 lines each, but `PublicTemplate#css_link` does `link.gsub!("oddb.css", "oddb-#{style}.css")` on a `<style>` block whose content *is* the CSS — the filename does not occur in it (0 occurrences in a rendered page), the substitution matches nothing, and `gsub!` returns nil while the method returns the unchanged block. Picking blue or red therefore only changes the logo. Broken since the stylesheet started being inlined by `HtmlGrid::TemplateMethods.get_inline`.
- **Wired into `css_links`, not `javascripts`** — `centeredsearchform`, `patinfo`, `fachinfo` and `interaction_chooser` all override `javascripts` **without calling `super`** (they start with `scripts = ""`), so a hook there is lost on the most visited pages. `css_links` is overridden nowhere in the tree and renders last in the `<head>`, which is exactly the order an overlay needs.
- The choice lives in `localStorage`, is applied before first paint, and follows `prefers-color-scheme` until the user decides otherwise. Both storage calls are wrapped in try/catch — `localStorage` throws in private windows and with site data blocked.
- **The generator has two blind spots, and both cost readability until August 2026.** It reads `oddb.css` and `diff.css` only, so it never saw `background: #eee` on `pre` — that comes from the vendored `tundra.css` via `@import`, and `pre` is exactly where the Fachinfo's column-aligned tables live (light text on light grey, 1.2:1). And it cannot see **inline styles written from Ruby**: `sdif_interaction.rb` sets the interaction severity colours (`#caff70`, `#ffec8b`, `#ff82ab`, `#ff6a6a`) and the source/route/combination badges (`#d5ecd5`, `#e8e0f0`, `#dff0d8`, `#dde8f0`) as `style="background-color: …"`, which left light text on pink at 1.7:1 and "Quelle: EPha.ch" at 1.1:1. Both fixed in the hand-written tail; the inline case with the general rule `[style*="background-color"]`, which is safe because **every** inline background in the application is light and none is dark. The light text there is inherited, not set by a rule, so normal specificity suffices and no `!important` is needed.
- **Figures in FI/PI get a white plate, not an inversion** (`img[src*="/images/fi/"]`) — in a medical figure the colours carry meaning.
- **Find these by measuring, not by reading.** Walk every leaf element, compute the WCAG ratio of its colour against the first non-transparent background up the chain, and list everything under 3.5:1. Four pages, four findings, and the result-list and detail pages came back clean. And seed `localStorage` (`oddb-theme` = `dark`) **before** the page's scripts run — injecting `data-theme` into the markup does nothing, because `darkmode.js` removes it again.
- **`dark.css` needs `git add -f`**: `.gitignore` excludes `doc/resources/**/*.css` (aimed at vendored dojo and logo material), yet all 18 of the project's own stylesheets are tracked through it the same way.
- A template change needs an app restart (`svc -t /etc/service/oddb`); the static files under `doc/resources/` do not.

### Responsive (`doc/resources/responsive.css`)

- **There was not one media query** in any of the nine own stylesheets, while `publictemplate.rb:55` has always declared `width=device-width`. A 16-column table with fixed pixel widths on a 390px screen ends after the fourth column.
- An **overlay on the dark.css pattern**: one file on the shared class names, wired into `css_links` in `publictemplate.rb` (never `javascripts` — `centeredsearchform`, `patinfo`, `fachinfo` and `interaction_chooser` override it without `super`). `.gitignore` excludes `doc/resources/**/*.css`, so it needs `git add -f`.
- **Two invariants, both tested** (`test/test_view/responsive.rb`): every declaration inside a media query, so nothing outside the breakpoints changes for anybody; and **no fixed colours**, because the file is embedded into every page and must be right in dark mode — a separator is `color-mix(in srgb, currentColor 18%, transparent)`, an unwanted background is `none`, never a hex.
- **Columns are addressed by name, not position.** `result_list_components` is overridden six times in `lookandfeelwrapper.rb` — `price_public` is column 9 in gcc, 8 or 5 elsewhere — so `:nth-child` is useless. `View::LookandfeelComponents#reorganize_components` appends `col-<key>` to both `@css_map` and `@css_head_map`; that one change (one method, every list that uses it) is what makes the phone card layout possible. String keys (`"nbsp"`, `"result_item_start"`) get none. Tests: `test/test_view/lookandfeel_components.rb`.
- **The skeleton rule is where exceptions belong, and this cost four broken layouts in one day.** The rule that turns the nested layout tables into blocks carries a `:not(:has(…))` per exception, and every exception raises its specificity — so it beats anything further down that wants a different `display`. It won against the card rows (twice), the header rows, the chapter navigation and the footer's flex column. The lesson is written into the file: **anything that needs another `display` is excluded THERE, never answered with more specificity here.** The current exclusions are `td.col-name_base` (pack rows → cards), `td.chapter-tab` (chapter navigation → chip band), `th` (header rows → hidden) and `td.subheading` (footer → reversed order).
- **`table.composite` is two different things.** It is both the page skeleton of nested layout tables and real data tables. Treating both as skeleton turned a sequence's package list into a column of right-aligned single values. They are distinguishable: **a data table has a header row of `th`, a layout table does not.** Data tables that get no card treatment stay tables and scroll inside themselves — their columns are the information.
- **A scrolling table must not also be `width: 100%`** — forced into 390px it squeezes instead of scrolling, and `4.13` comes out as three lines of one digit. But not `max-content` either: that forbids wrapping and made the registration view's rows 1049px. `width: auto` with `min-width: 100%` on the tbody is the pair that works.
- **`table-layout: fixed` on the skeleton destroys the cards** — the outer tables then split their columns by the first row, the name column ends up a few pixels wide, and every letter sits on its own line. It is right on `table.left` (a leaf table with a set width and nothing nested) and wrong everywhere else. `max-width` does **not** force a table below its minimum content width; making the skeleton blocks is what caps it, because a block takes its parent's width instead of asking its content.
- **`flex-grow` cannot force a line break.** A flex container fills a line first and distributes leftover space afterwards, so the FI/PI marks kept sliding up next to the price whenever the name and price left room. Three attempts with grow and auto margins each fixed one flavor and broke another. What works is an actual break element: `compactdetail.js` inserts an empty cell with `flex-basis: 100%` and zero height in front of the first visible mark. Note the trap that followed: `td:empty { display: none }` then hid the break, which is empty on purpose.
- **What CSS cannot do here, the script does.** A cell holding only `&nbsp;` is not `:empty`, and CSS cannot look at text — so `doc/resources/javascript/compactdetail.js` hides blank label/value pairs in the detail view (12 per page), blank cells in the cards (58 on a result list, 73 on the query-limit page), the footer's spacer cell and the ATC band's second cell. The footer cell is the reason it must check content and not the class: the same cell holds a `&nbsp;` for anonymous visitors and the greeting for signed-in ones.
- **Specificity bit twice more, the same way it did in dark mode.** `table:has(> tbody > tr > td.col-name_base) > tbody > tr { display: block }` is (0,1,4) and beat `tr:has(> th.col-name_base) { display: none }` at (0,1,2) — the header row stayed and the rows stacked as blocks instead of flexing. And a generic `tr:has(...) > td { display: block }` at (0,1,3) silently re-showed the columns the 1024px block had hidden.
- **`overflow-wrap: anywhere`, not `break-word`**, on `td.atc`: the ATC band glues its text with `&nbsp;` into one 650px unbreakable word, and a table cannot go below its widest content. Only `anywhere` lowers min-content. `td.list` set `break-word` later in the file at the same specificity and undid it — hence `td.list:not(.atc)`.
- **What actually made the page scroll sideways**, measured at 390px, in order: the AdSense iframe (504px, now off), the zone navigation as a single table row (937px), the header table's two columns sharing widths, the footer navigation tables, and the ATC band. Nothing is over the viewport at 390, 768 or 1400px now.
- **16px on inputs is not taste**: Safari zooms the page when a field under 16px takes focus and never zooms back.
- **`overflow-wrap: anywhere` is for long words, not for headings.** It lowers a box's minimum width by breaking inside words, which is what substance names need — and what turned a six-letter column title into `St / är / k / e`. Headings get `break-word`, numeric columns get `nowrap`. And `td.right` is too broad for that `nowrap`: it also catches `td.explain.right`, the hint under the result list, which then stands as one 710px line.
- **Views that build their columns positionally get no `col-*` classes.** `ResultLimitList` (the query-limit page) and `View::Drugs::CompareList` both bring their own `reorganize_components`; the first has its CSS maps written out per column now, the second shares the helper through `View::ColumnCssClass`. And a table is identified as a result list by what its **rows** carry, not its header — the mobile flavor builds its list with three-part component keys, so its header cells have no `col-name_base` at all.
- Verify by measuring, not by looking: headless Chromium, `document.body.scrollWidth` against `clientWidth`, and a contrast walk over every leaf element. Snap Chromium cannot write to `/tmp` and hangs on `file://` — write screenshots under `$HOME` and serve pages over `127.0.0.1`. **Measure every flavor**: gcc and mobile build the same list differently, and a fix verified on one broke the other three times.
- **`responsive.css` is inlined into every page and is always current; `compactdetail.js` is a file the browser caches.** A change to the script needs a reload without cache to be visible.

### External links open in a new tab (`doc/resources/javascript/externallinks.js`)

- Every link to a foreign host gets `target="_blank"` and `rel="noopener noreferrer"` — without `noopener` the opened page can reach back through `window.opener`.
- **One script rather than edits in the views**: the links are built in over two hundred places and a good part of them sits inside Fachinfo text that comes out of a parser. Hooked into `css_links` for the same reason the dark mode is — the most visited pages override `javascripts` without calling `super`. A `MutationObserver` catches what the autocomplete and the interaction chooser add later.
- Own-host links stay put, absolute ones included: the application writes its links with its own host, and comparing `link.hostname` against `location.hostname` is what tells them apart. `mailto:`, `tel:` and bare anchors are skipped, and an already-set `target` is left alone.

### AdSense is off (August 2026)

- `ENABLED = false` in `View::GoogleAdSenseMethods` (`src/view/google_ad_sense.rb`). Unused, but every page still shipped the `pagead2.googlesyndication.com` script, the `<ins>` and the publisher id, and the iframe it pulled was 504px — the last cause of sideways scrolling on a phone.
- **The switch cannot live in the lookandfeel.** `SBSM::Lookandfeel#enabled?(event, default = true)` is `default || ENABLED.include?(event)` — with the default `true` everything is on and removing a key from an `ENABLED` array changes nothing. Verified by trying it: the ads still shipped.
- The `<ins>` inline style was broken twice: `style="display:block height  #{@height}px width {@width}px"` — no colons or semicolons, so the browser dropped the whole declaration and not even `display:block` applied, and `{@width}` was a placeholder missing its `#`. Size comes from the `<style>` block above it, which is per screen width.
